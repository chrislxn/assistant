## M4.1：core-blocks CRUD API

**新增 3 个端点：**

- `GET /core-blocks` — 列出所有 active approved core blocks
- `GET /core-blocks/{block_key}` — 查单个 active approved block，不存在返回 404
- `POST /core-blocks/{block_key}` — 创建新版本，调用 `create_core_block_version()`，不原地覆盖

**关键规则：**
- GET 只返回 `approval_status='approved' AND superseded_at IS NULL` 的最新版本
- POST 重复写同一 block_key → 旧版本 `superseded_at=NOW()`，新版本 `version_no+1`
- POST 默认 `auto_approve=True`（手动 API 调用直接审批）
- 端点加入 `PROTECTED_PREFIXES`（`/core-blocks`），受 `AdminAuthMiddleware` 保护
- 不改 startup 迁移、不改 get_persona、不改 context injection、不开放 AI/MCP

**文件改动：** `kiwi-mem/main.py` +106 行（3 端点 + 1 protected prefix）

## M4.2：__BOT_PERSONA__ 迁移到 core_blocks.response_policy

**迁移逻辑（`database.py` 新增 `migrate_persona_to_core_block()`）：**

1. 查询 core_blocks 是否已有 active `response_policy` → 有则跳过
2. 查询 memories 中 `title='__BOT_PERSONA__'` → 无则跳过
3. 调用 `create_core_block_version(block_key='response_policy', ..., proposed_by='migration', approved_by='migration', auto_approve=True)`
4. 将原 memory 标记 `status='archived'`, `memory_type='core_legacy'`，不删除
5. 任何异常 catch + warning，不阻止服务启动
6. 幂等：重启多次只产生 1 个 active block

**扩展 `create_core_block_version()`：** 新增 `approved_by` 参数（可选，默认 None）。

**调用点：** `main.py` `lifespan()` 中，在工厂 prompt 初始化之后执行。

**文件改动：**
- `kiwi-mem/database.py` +35 行（`migrate_persona_to_core_block` + `approved_by` 参数）
- `kiwi-mem/main.py` +7 行（import + lifespan 调用）

## M5.2：memory_access_log 写入

**kiwi-mem `/v1/chat/completions`：**

- 在 `build_system_prompt_with_memories()` 内收集 `injected_core_keys` + `injected_legacy_ids`
- 存入 `prompt_meta["_injected"]`
- `chat_completions()` 生成 session_id 后，`asyncio.create_task(log_memory_access(...))`
- actor='api_client', retrieval_mode='chat_completions', intent='chat'

**telegram-bot `_process_message()`：**

- 新增 `_log_access()` helper（直写 asyncpg 到 `memory_access_log`）
- 收集 `injected_core_keys`（response_policy + active_projects 实际注入的）
- `asyncio.create_task(_log_access(...))` fire-and-forget
- actor='telegram_bot', retrieval_mode='telegram_bot', intent='chat', session_id=CHAT_ID
- legacy_memory_ids 传空数组（bot 侧 HTTP 拿到的搜索结果已格式化为文本，无法提取 IDs）

**安全措施：**
- logging 失败 catch + warning/pass，不影响聊天回复
- core_block_keys 只记录白名单内实际注入的块，test.block 绝不出现

**文件改动：**
- `kiwi-mem/main.py` +30 行（ID 追踪 + log 调用）
- `telegram-bot/bot.py` +28 行（`_log_access` helper + 调用）

## M4.1：core-blocks CRUD API

**新增 3 个端点：**

- `GET /core-blocks` — 列出所有 active approved core blocks
- `GET /core-blocks/{block_key}` — 查单个 active approved block，不存在返回 404
- `POST /core-blocks/{block_key}` — 创建新版本，调用 `create_core_block_version()`，不原地覆盖

**关键规则：**
- GET 只返回 `approval_status='approved' AND superseded_at IS NULL` 的最新版本
- POST 重复写同一 block_key → 旧版本 `superseded_at=NOW()`，新版本 `version_no+1`
- POST 默认 `auto_approve=True`（手动 API 调用直接审批）
- 端点加入 `PROTECTED_PREFIXES`（`/core-blocks`），受 `AdminAuthMiddleware` 保护
- 不改 startup 迁移、不改 get_persona、不改 context injection、不开放 AI/MCP

**文件改动：** `kiwi-mem/main.py` +106 行（3 端点 + 1 protected prefix）

## Phase 1.0 M2 — Candidate Resolver

**目标：** 实现 `resolve_candidate()`，让 candidates 不再永远 pending。

**规则（按优先级）：**
- R4: health_pattern / health_baseline → requires_review (always)
- R5: identity_fact / relationship_context / risk_flag / policy_rule → requires_review (unless user_direct)
- R6: diagnosis-like keywords → requires_review (unless user_direct)
- R1: assistant_inferred / claude_mcp / hermes_agent → keep_pending
- R2: user_direct + low-risk → auto_commit
- R3: system_generated + health_observation_summary → auto_commit
- R7: conflict on (subject_key, predicate_key) → supersede or keep_pending

**关键设计：**
- `assistant_inferred` 永远不 auto_commit（无论 confidence）
- Low-risk whitelist：preference / project_state / project_decision / procedure / episodic_event / device_inventory / external_fact / project_knowledge / health_observation_summary
- 未知类型默认 keep_pending（不因"不是 high-stakes"就 auto_commit）
- Dual-write：memory_items + memories (compat)
- Transaction 包裹：conflict lookup → supersede → insert items → insert memories → update candidate
- Supersede 安全：只有 can_auto_commit=True 后才执行 UPDATE

**test script:** `scripts/test_resolver_scenarios.py` — 28 assertions, 7 scenarios

**修复（review 后）：**
- BLOCK-1: conflict/supersede side-effect 移到 can_auto_commit 确认后
- BLOCK-2: async with conn.transaction() 包裹全部写入
- WARN-1: 使用 low-risk whitelist 替代 high-stakes blacklist
- WARN-2: 显式检查 extractor_name 拦截 claude_mcp/hermes_agent
- WARN-B: actor_scope 从 candidate 继承，不硬编码
- WARN-C: committed_memory_id tech debt 记录（Phase 1.2）

## Phase 1.0 M3 — Review Queue API

**目标：** 最小 pending candidates 审核 API。

**端点：**
- `GET /admin/candidates?status=pending&limit=20` — 列出（含 age_days）
- `GET /admin/candidates/{candidate_id}` — 详情
- `POST /admin/candidates/{candidate_id}/commit` — 人工批准（force_commit=True）
- `POST /admin/candidates/{candidate_id}/reject` — 人工拒绝

**Helpers：**
- `list_candidates(status, limit, source_trust, memory_type)` — 筛选 + age_days
- `get_candidate(candidate_id)` — 单条全字段
- `reject_candidate(candidate_id, reason)` — 状态保护 + idempotent
- `resolve_candidate(candidate_id, force_commit=False)` — M2 resolver + 人工批准路径

**force_commit 边界：**
- 跳过所有 auto guard checks（R1/R4/R5/R6）
- 仍保留 transaction + conflict/supersede 安全
- 只能通过受 AdminAuthMiddleware 保护的 admin endpoint 触发

**状态保护：**
- committed → recommit: error 409 "already committed"
- committed → reject: error 409 "cannot reject"
- rejected → commit: error 409 "already rejected"
- rejected → re-reject: idempotent 200

**修复（review 后）：**
- WARN-1: age_days 公式改为 EXTRACT(EPOCH FROM ...)/86400
- WARN-2: reviewed_by 写固定值 'admin'
- WARN-3: HTTP 状态码 404/409/400 分流
- WARN-4: list 结果使用 _serialize_candidate()
- WARN-6: PROTECTED_PREFIXES 移除冗余 "/admin/candidates"
